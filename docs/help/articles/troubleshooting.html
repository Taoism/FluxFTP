Troubleshooting

Connection times out

Confirm the host, port, protocol mode, proxy, firewall rules, and server availability. For FTP, passive-mode data ports may need to be allowed by the server firewall. Try Connection Diagnostics to identify which stage fails.

Authentication or trust fails

Check the username and authentication method. For FTPS, verify the server certificate and hostname. For SFTP/SCP, compare the SSH fingerprint through a trusted channel. Do not accept an unexpected identity change without checking with the server owner.

Transfer cannot resume

Resume depends on protocol, server capability, and destination state. SCP, direct FXP, and some cloud operations do not support byte-offset resume. Choose an available overwrite or restart action when needed.

Remote-to-remote copy fails

Both FTP servers must permit FXP and agree on a usable data route. Try Auto roles, check server policy, or use a relay transfer. Protected FTPS FXP requires compatible SSCN or CPSV support.

More detail

Review the application log and Transfer History. Diagnostic exports may include hostnames and paths; inspect them before sharing.
