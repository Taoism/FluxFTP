Deployments and rollback

Deployment Profiles save a local source folder, remote destination, exclusions, and verification policy. Preview the plan first; preview reads both sides without writing. Approve the reviewed plan to add it to the queue.

Create or edit a profile to import a GitLab pipeline artifact or GitHub Actions artifact as its local source. Enter an HTTPS GitLab server, project ID or path, branch/tag and read API token; or a GitHub owner/repository, branch/tag and Actions-read token. Or choose Sign in with GitLab/GitHub to open the provider's one-time-code page. FluxFTP can remember the authorized token in its encrypted credential vault. Enter the OAuth application ID once per provider/server; GitLab applications need the device_code grant and read_api scope. GitHub Apps need device flow enabled and Actions read permission. FluxFTP rotates expiring GitHub access tokens using the saved refresh token; sign in again when that refresh token expires or is revoked. Manual token entry remains available. Choose a successful pipeline/workflow run and artifact. Downloads are size-limited and safely extracted; unsafe paths, links, special files and case-insensitive duplicate paths are rejected. Provider, project/repository, ref, run/pipeline, commit and artifact provenance are retained in the profile and rollback journal.

Before overwriting changed destination files, FluxFTP retains local backups. Verification prefers a native SHA-256 checksum and otherwise downloads content for comparison. Size-only verification does not prove content equality. Destination-only files and empty folders are retained.

Rollback previews a retained revision, checks backup integrity and current remote content, and blocks restoration when later changes make it unsafe. Journals and backups live locally beside the configured sites file and remain until removed. Rollback restores file content, not original permissions or timestamps; deployment is not an atomic release and cannot lock out external writers.
