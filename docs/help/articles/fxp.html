Remote-to-remote transfers (FXP)

When both panes are connected to compatible FTP or FTPS servers, FluxFTP can ask the servers to transfer data directly using FXP. The file payload then does not pass through this computer. If direct FXP is unavailable, use a relay transfer through this computer where supported.

Automatic and reverse routes

With both FTP sites' FXP data roles set to Auto, FluxFTP tries a passive destination route first. If route setup fails before RETR/STOR begins, it tries the passive source route. This automatic reverse attempt helps with servers that permit only one side to initiate the data connection. Explicit site roles select a route and turn off that automatic retry.

Each server must support the selected FXP mode and permit transfers to the other server. Protected FTPS FXP additionally requires server support for SSCN or CPSV; FluxFTP does not downgrade protected data to clear text. Check the server's policy and logs when FXP is denied.
